## What was successfully tested [OBSERVED]

- Existing EcoNet/ZTE bootloader loaded the image into RAM and jumped to it; original SPI NOR not written.
- Ethernet modules and MT7530 MMIO DSA switch came up automatically; `br-lan` included `port0`, `port1`, `port2`, `port3` and used `192.168.1.1`.
- `cat /proc/sys/net/core/default_qdisc` returned `pfifo_fast`.
- Exactly **256** `eth0` BQL `limit_min` entries reported **32768** bytes.
- USB xHCI initialised; a Kingston DataTraveler 3.0 was detected, approximately 61.9 GB, with `/dev/sda` and `/dev/sda1` block devices.
- Kernel log checks during the reported session showed no OOM or panic.
- Reported runtime reached **27 minutes**, including sustained traffic, without observed OOM. This is **not** extended uptime validation.

## Network performance [OBSERVED / DERIVED]

**Test direction:** H168N downloads HTTP file served by Ubuntu laptop `192.168.1.3:8080`. The H168N receives data through its CPU-facing network path; this is **not** LAN-to-LAN forwarding throughput.

```sh
for i in 1 2 3; do
    echo "TEST $i"
    time wget -q -O /dev/null http://192.168.1.3:8080/test128m.bin
done
```

The test file was 128 MiB (134,217,728 bytes); timings were **15.89 s, 15.84 s and 15.78 s**. Corresponding calculated rates (`bytes × 8 / elapsed_seconds`) are **67.6, 67.8 and 68.1 Mbit/s**, averaging approximately **67.8 Mbit/s**. Earlier repeat tests showed similarly consistent times around 15.9–16.2 s.

Earlier LAN-to-LAN switching tests observed approximately **94–95 Mbit/s** on 100 Mbit/s physical links. Those measurements were separate and are *not* proof of 95 Mbit/s through the router's CPU stack.

### Latency observation [OBSERVED, unresolved]

Pings to the router's CPU often showed a recurring approximately **1–10 ms sawtooth**, including stretches without cable changes. Periods of `Destination Host Unreachable` and long RTTs occurred during **deliberate cable moves**, so those ping summaries are not representative of continuous stable-link performance. Ping to a Windows host through the switch was generally much lower latency. The origin of the repeating CPU RTT pattern remains unproven.

## How the tested image starts Ethernet

- `files/lib/preinit/05_h168n_qdisc` sets default qdisc before driver registration.
- `files/etc/init.d/h168n-ethernet` loads `mt7530`, `mt7530-mmio`, then `econet-eth` and sets BQL minima on the created TX queues.
- `files/etc/rc.d/S12h168n-ethernet` enables that init script early.
- `files/etc/config/network` adds four DSA ports to `br-lan`.
- Original global package autoload was removed in this development build to control ordering. This modification affects the shared `econet-eth` package, so it **must not be advertised as a board-independent upstream solution**.
- `mt7530-mdio` is packaged but intentionally not loaded on this MMIO switch board.

## Not yet validated

Repeated cold boots, >24-hour stability, Wi-Fi/PCIe radio operation, LuCI, USB filesystem mounting, firewall/WAN routing/PPPoE/NAT performance, flash installation, recovery from failed flash writes, and factory firmware formatting. Do not infer those from the positive LAN and USB results.
