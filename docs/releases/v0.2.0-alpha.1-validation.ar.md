## النتائج اللي اتشافت فعلًا — OBSERVED

- Bootloader استقبل الـ image في RAM وشغّل Linux/OpenWrt، ومفيش كتابة على Flash.
- `mt7530` / `mt7530-mmio` / `econet-eth` اشتغلوا أوتوماتيك؛ `br-lan` فيها `port0` و`port1` و`port2` و`port3` وعنوانها `192.168.1.1`.
- `/proc/sys/net/core/default_qdisc` أظهر `pfifo_fast`.
- ملفات BQL في `eth0` أظهرت `256 32768`، يعني كل 256 TX queues متضبطين على نفس الحد الأدنى.
- USB xHCI اشتغل؛ Kingston DataTraveler 3.0 ظهر بحوالي 61.9 GB و`/dev/sda1`.
- Kernel log أثناء الجلسة مفيهوش OOM أو Panic. Uptime المسجل وصل 27 دقيقة على الأقل؛ ده مش اختبار استقرار لعدة أيام.

## طريقة اختبار Ethernet

**الاتجاه:** الراوتر بيحمّل ملف HTTP من جهاز Ubuntu على `192.168.1.3:8080`. ده اختبار **الـ CPU path**، مش اختبار switching بين منفذين ولا سرعة NAT.

```sh
for i in 1 2 3; do
    echo "TEST $i"
    time wget -q -O /dev/null http://192.168.1.3:8080/test128m.bin
done
```

ملف كل Test = **128 MiB = 134,217,728 bytes**. الأزمنة: **15.89 / 15.84 / 15.78 ثانية**. الحساب `size × 8 / seconds` يدينا **67.6 / 67.8 / 68.1 Mbps**، بمتوسط نحو **67.8 Mbps**. اختبار منفصل بين جهازين داخل الـ LAN حقق سابقًا 94–95 Mbps تقريبًا، لكن مش معناه إن الراوتر بيعمل Routing بنفس السرعة.

### العدادات قبل/بعد الثلاث Tests

| Interface | RX drops قبل | RX drops بعد | RX errors / TX errors / TX drops |
| --- | ---: | ---: | --- |
| `eth0` | 0 | 0 | 0 / 0 / 0 |
| `port0` | 3 | 3 | 0 / 0 / 0 |
| `port1` | 0 | 0 | 0 / 0 / 0 |
| `port2` | 4 | 4 | 0 / 0 / 0 |
| `port3` | 3 | 3 | 0 / 0 / 0 |

إذن **مفيش drops جديدة حسب العدادات المعروضة** أثناء الاختبار. ده لا يثبت إن مفيش Packet loss على أي طبقة مطلقًا. قبل الاختبار، نقل كابلات Ethernet بين فتحات الراوتر عمل فترات فقد Ping، فما ينفعش نستخدم أرقام الفقد وقت الفصل لتقييم وصلة ثابتة.

### تذبذب Ping

ظهر نمط صعود ونزول متكرر حوالي **1–10 ms** في ICMP للراوتر نفسه، حتى بين فترات تبديل الكابلات. سبب الـ sawtooth غير معروف؛ CPU scheduling وInterrupts وQDMA احتمالات، مش نتائج مؤكدة.

## الذاكرة

بعد 384 MiB إجمالي نقل في آخر 3 Tests:

```text
MemAvailable: 7256 kB

```

قراءات الجلسة كانت متقاربة، لكن ده **مش ضمان بعدم وجود leak** أو بعدم OOM تحت ضغط مختلف.

## USB

```text
xhci-mtk 1fb90000.usb: xHCI Host Controller
usb 1-2.2: device descriptor read/64, error -71
usb-storage 1-2.2:1.0: USB Mass Storage device detected
scsi 0:0:0:0: Direct-Access Kingston DataTraveler 3.0
sda: sda1
```

التحذير `-71` ما منعش اكتشاف الـ Kingston، لكن سببه مش مثبت. USB filesystem mounting وUSB throughput مش مختبرين.

## ترتيب تشغيل Ethernet تلقائيًا

- ملف `files/lib/preinit/05_h168n_qdisc`: بيضبط الـ qdisc بدري.
- ملف `files/etc/init.d/h168n-ethernet`: بيحمّل `mt7530` ثم `mt7530-mmio` ثم `econet-eth`، ويطبق BQL.
- `files/etc/rc.d/S12h168n-ethernet`: تشغيل Init script أثناء الإقلاع.
- `files/etc/config/network`: بيساوي Bridge بين أربع فتحات LAN.

إلغاء Autoload من Package العام تعديل تجريبي للتأكد من الترتيب؛ **مش حل عام معتمد لكل أجهزة EcoNet**. `mt7530-mdio` موجود في الحزمة لكن **مش بيتم تحميله** على الجهاز صاحب MMIO switch.
